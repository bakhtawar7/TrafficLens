# Wireframe and interaction map

This document describes the current Streamlit interface by reading the tab renderers. It is
a functional map, not a claim that a formal usability study has been completed. The visual
polish checklist and first-time user protocol are in `docs/usability_test.md`.

TrafficLens results are a pilot on Dhaka imagery. Reference counts are human counts with a
documented mean absolute pass difference of 1.62 vehicles (95% scene-bootstrap interval
0.67–2.46; 13 paired images across 7 scenes). The optional fine-tuned rickshaw detector is a
separate model with its own evaluation and contamination exclusions.

## Overall frame

```text
+--------------------------------------------------------------------------+
| TrafficLens                                                              |
+----------------------+---------------------------------------------------+
| SIDEBAR              | [Image] [Video] [Reliability] [Evaluation] [History]|
| Input                |                                                   |
|  Upload an image     |                  ACTIVE TAB                      |
| Classes to count     |                                                   |
| Confidence threshold |                                                   |
| Base model: YOLOv8n  |                                                   |
| Sliced inference     |                                                   |
| Limitations          |                                                   |
+----------------------+---------------------------------------------------+
```

## Sidebar

| Control | Current behaviour |
| --- | --- |
| Upload an image | JPG/JPEG/PNG/WEBP, subject to configured upload size. |
| Classes to count | Select one or more configured COCO vehicle classes. Empty selection prevents counting. |
| Confidence threshold | Filters detections below the selected confidence. Cached model resources are shared; moving the slider should not reload weights. |
| Base model indicator | Displays YOLOv8n as the Image tab's base detector. |
| Sliced inference | Applies to the Reliability tab's comparison workflow, not the Image tab's primary count. |
| Limitations | Persistent caveats covering occlusion, small/distant objects, local vehicle types, pilot scope, and video limitations. |

## Image tab

- Empty state asks the user to upload an image.
- Shows original and annotated image, total and per-class metrics, inference time, detections,
  and JSON/CSV downloads.
- Optional zone analysis accepts polygon vertices in original image pixel coordinates and
  reports descriptive per-model zone measures.
- Optional rickshaw-aware toggle runs a separate fine-tuned one-class rickshaw model. Its
  output is not a replacement for the pretrained multi-class count and has separate
  evaluation/contamination status.
- Upload validation, decode errors, and detector failures are surfaced as user-facing
  messages. History write failure is a warning and should not block the count.

## Video tab

- Requires a licensed video upload and a matching provenance row in
  data/samples/video/PROVENANCE.csv.
- Displays a first-frame preview and accepts directed virtual-line start/end coordinates.
- Uses local pretrained weights only; the video path does not download weights.
- Produces inbound/outbound crossing totals, annotated video, and a crossing CSV.
- Video has not been evaluated against labelled video ground truth. Track identity switches
  and duplicate IDs during occlusion can affect crossings; no accuracy claim is made.

## Reliability tab

- Compares the registered pretrained detectors on the current image.
- Reports per-model counts, count range, count disagreement and box agreement.
- Optional sliced inference changes how comparison detections are produced.
- Reliability values describe model-to-model agreement, not correctness.
- The needs-review flag must display “not yet validated” when the validated prediction
  configuration is unavailable. H1/H2 remain not tested under the current pilot evidence.

## Evaluation tab

- Reads benchmark/evaluation artefacts generated by the offline scripts.
- Displays human-reference comparisons and descriptive results when the expected evaluation
  table exists; otherwise shows an explicit placeholder.
- Human pass-consistency information must not be confused with model accuracy.
- H1 and H2 are not tested; H3 and H4 are descriptive only under the current evidence.

## History tab

- Discloses that filenames and run metadata are stored locally; image bytes are not stored.
- Run-history view supports filename/model filters, details, CSV export, per-run deletion,
  and clear-history confirmation.
- Human review queue sorts flagged runs first, then other runs oldest first. If flags are
  not validated, the ordering is described as based on model disagreement.
- Reviewer re-uploads the exact original image (SHA-256 match), enters seven category counts
  while blind to model results, then reveals the comparison.
- Corrections are append-only user-reported data. They do not modify LABELS.csv, models, or
  settings.

## Narrow-window and polish checklist

The following items are design checks, not claims of completed visual verification:

- [ ] Verify tab navigation remains usable at narrow desktop/tablet widths.
- [ ] Check text contrast and readability at normal browser zoom.
- [ ] Use consistent heading hierarchy, spacing, empty states, and error presentation.
- [ ] Confirm long tables and images do not force horizontal page overflow.
- [ ] Confirm loading indicators explain which model is loading and when.
- [ ] Add concise help text to any remaining controls without help text.
- [ ] Run the first-time usability protocol in docs/usability_test.md and record results
      in results/usability/results_filled.csv.
